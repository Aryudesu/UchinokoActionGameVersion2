# UchinokoActionGame 新設計方針

既存の素材とステージデータを維持しながら、ゲームを動作単位ごとに新設計へ移行する。
移行中も旧実装を起動可能な状態に保ち、一度に全面置換しない。

## 素材配置

実行時の基準ディレクトリはソリューションディレクトリとし、素材は次の位置へ置く。

```text
UchinokoActionGameVersion2/
├─ Actgame.sln
├─ Actgame/
└─ dat/
   ├─ img/
   ├─ SE/
   ├─ BGM/
   ├─ stage/
   └─ wmap/
```

コードではパスを直接連結せず、`Foundation/AssetPaths` を使用する。

## 移行段階

1. 共通基盤
   - 素材パス
   - 読込結果とエラー
   - 座標型
   - タイルマップ
   - ゲームモード
2. ワールドマップ
   - 表示、移動、壁判定、ステージ選択、セーブ座標検証
3. アクションゲーム
   - ステージ、プレイヤー、ブロック、敵、アイテム、ギミック
4. 倉庫番
   - 箱、目的地、移動、リセット、クリア判定
5. 会話、セーブ、音声、演出
6. 旧実装の撤去

## 基盤の責務

- `AssetPaths`: `dat` 以下のパスを一元的に生成する。
- `Result<T>`: 失敗を強制終了や空配列に変換せず、呼出側へ理由とともに返す。
- `GridDataLoader`: `.ary` の整数グリッドを読み込み、空データ、不正値、行幅不一致を検出する。
- `TileMap`: ワールド座標とタイル座標を変換し、範囲外をポインタの `nullptr` または `false` で返す。
- `TileCatalog`: タイルIDに画像・当たり判定形状・破壊可否・ダメージ属性を割り当てる。
- `TerrainCollision`: 通常床、すり抜け床、左右の坂道の接地面を計算する。移動後の足元を上下に探索して坂道への接地を維持する。
- `LayeredMap`: 地形、見た目、オブジェクト、イベントを同じ大きさの独立レイヤーとして保持する。
- `GameMode`: アクションと倉庫番を型で区別し、不明なモードをエラーにする。

ゲームロジックから `Data[y][x]` を直接使用せず、必ず `TileMap` を経由する。

## マップデータの拡張方針

タイルIDそのものに処理をハードコードせず、`TileDefinition` の設定で性質を決める。
ブロックを増やす場合は、まず既存の当たり判定形状と属性の組合せで定義し、形状計算が本当に異なる場合だけ `CollisionShape` を追加する。

マップは次の4レイヤーに分ける。

| レイヤー | 内容 |
|---|---|
| Terrain | 壁、床、坂道などの当たり判定 |
| Visual | 背景や装飾など当たり判定を持たない表示 |
| Object | プレイヤー、敵、箱、アイテムの初期配置 |
| Event | ゴール、ワープ、会話開始地点など |

この構造はアクションゲームと倉庫番で共用する。既存の `.ary` は段階的に変換し、将来のマップ編集ツールも同じ4レイヤーを出力する。

## 坂道テスト

`Actgame` のメニューから `Slope test` を選ぶと、新設計の移動と地形衝突を素材なしで確認できる。

- 左右キー: 移動
- `Z`: ジャンプ
- `Esc`: メニューへ戻る

黄色い矩形がプレイヤー、青い矩形が通常ブロック、緑の三角形が坂道を表す。
この画面は移行中の動作確認専用であり、既存のアクションゲームや倉庫番の処理は変更しない。
