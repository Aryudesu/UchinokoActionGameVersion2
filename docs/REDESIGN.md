# UchinokoActionGame 新設計方針

既存の素材とステージデータを維持しながら、ゲームを動作単位ごとに新設計へ移行する。
移行中も旧実装を起動可能な状態に保ち、一度に全面置換しない。

## 素材配置

実行時の基準ディレクトリはソリューションディレクトリとし、素材は次の位置へ置く。

```text
UchinokoActionGameVersion2/
├─ Actgame.sln
├─ Actgame/
└─ dat/
   ├─ img/
   ├─ SE/
   ├─ BGM/
   ├─ stage/
   └─ wmap/
```

コードではパスを直接連結せず、`Foundation/AssetPaths` を使用する。

## 移行段階

1. 共通基盤
   - 素材パス
   - 読込結果とエラー
   - 座標型
   - タイルマップ
   - ゲームモード
2. ワールドマップ
   - 表示、移動、壁判定、ステージ選択、セーブ座標検証
3. アクションゲーム
   - ステージ、プレイヤー、ブロック、敵、アイテム、ギミック
4. 倉庫番
   - 箱、目的地、移動、リセット、クリア判定
5. 会話、セーブ、音声、演出
6. 旧実装の撤去

## 基盤の責務

- `AssetPaths`: `dat` 以下のパスを一元的に生成する。
- `Result<T>`: 失敗を強制終了や空配列に変換せず、呼出側へ理由とともに返す。
- `GridDataLoader`: `.ary` の整数グリッドを読み込み、空データ、不正値、行幅不一致を検出する。
- `TileMap`: ワールド座標とタイル座標を変換し、範囲外をポインタの `nullptr` または `false` で返す。
- `TileCatalog`: タイルIDに画像・当たり判定形状・破壊可否・ダメージ属性を割り当てる。
- `TerrainCollision`: 通常床、すり抜け床、左右の坂道の接地面を計算する。移動後の足元を上下に探索して坂道への接地を維持する。
- `TerrainStageLoader`: ステージ設定、地形CSV、タイル定義CSVをまとめて読み込み、未定義IDなどを検出する。
- `LayeredMap`: 地形、見た目、オブジェクト、イベントを同じ大きさの独立レイヤーとして保持する。
- `GameMode`: アクションと倉庫番を型で区別し、不明なモードをエラーにする。

ゲームロジックから `Data[y][x]` を直接使用せず、必ず `TileMap` を経由する。

坂道は上面の接地判定に加え、左右端に存在する地形の垂直区間も持つ。
高い側へ横から進入した場合は壁として止め、低い側や連続する坂の継ぎ目は通過させる。
1×2の急坂では、斜面より下にある下段の半分も実体のある壁として扱う。

床と坂への接地高さは、キャラクターの足元中央1点から決定する。
左右角の高さを競合させないことで、急坂の頂上や谷でも接地面を一意にする。
横壁はCanvasMasaoと同様、キャラクター中央X上の頭側・足側2点で進行先タイルを判定する。
足側は身体の内側へ少しずらし、床面そのものを横壁として拾わないようにする。
空中では同じ列内でも移動方向側の壁を再確認し、上昇中に坂の側壁を抜けることを防ぐ。
接地中に坂面へ1フレームで登れる量を超えて入り込む場合は、坂上へ接地補正せず側面で停止する。
天井は頭上中央点で判定し、ジャンプ中に矩形の左右角だけが天井へ引っ掛からないようにする。
タイルの継ぎ目では頭上中央の左右1pxも補助確認し、中央点が境界の片側だけを参照して抜けることを防ぐ。
CanvasMasaoと同様、上昇して別のタイル行へ入った瞬間は、坂と階段のタイル全体を天井として扱う。
頭が既に坂タイル内にある場合はジャンプを許可し、斜面へ張り付いた状態で跳べなくなることを防ぐ。
すり抜け床だけは下から通過できる。

## マップデータの拡張方針

タイルIDそのものに処理をハードコードせず、`TileDefinition` の設定で性質を決める。
ブロックを増やす場合は、まず既存の当たり判定形状と属性の組合せで定義し、形状計算が本当に異なる場合だけ `CollisionShape` を追加する。

マップは次の4レイヤーに分ける。

| レイヤー | 内容 |
|---|---|
| Terrain | 壁、床、坂道などの当たり判定 |
| Visual | 背景や装飾など当たり判定を持たない表示 |
| Object | プレイヤー、敵、箱、アイテムの初期配置 |
| Event | ゴール、ワープ、会話開始地点など |

この構造はアクションゲームと倉庫番で共用する。既存の `.ary` は段階的に変換し、将来のマップ編集ツールも同じ4レイヤーを出力する。

## 坂道テスト

`Actgame` のメニューから `Slope test` を選ぶと、新設計の移動と地形衝突を素材なしで確認できる。

- 左右キー: 移動
- `Z`: ジャンプ
- `Esc`: メニューへ戻る
- `R`: 外部マップデータを再読み込み

黄色い矩形がプレイヤー、青い矩形が通常ブロック、緑の三角形が坂道を表す。
プレイヤー足元の赤い点が床と坂の接地点および横壁の足側判定点、
頭上中央の赤い点が横壁の頭側判定点と天井の主判定点を表す。実際の天井判定では左右1pxも補助的に確認する。
この画面は移行中の動作確認専用であり、既存のアクションゲームや倉庫番の処理は変更しない。

### 外部マップデータ

配置は `dat/stage/slope-test/` 以下の3ファイルで編集する。

| ファイル | 内容 |
|---|---|
| `stage.ini` | 使用するCSV、プレイヤー開始座標、タイルサイズ |
| `terrain.csv` | 1マスにつき1つのタイルIDを並べた地形 |
| `tiles.csv` | `ID,形状,画像番号,破壊可否,ダメージ属性` |

`terrain.csv` を保存してテスト画面で `R` を押すと、ゲームを再起動せず配置を確認できる。
未知のタイルID、形状名、CSVの列数・行幅の不一致、ファイル不足は画面上へエラーとして表示する。

2×1と1×2の地形は複数のタイルIDを正しい順番で組み合わせる。サンプルの
`terrain.csv` に左右両方向の配置例があり、そのまま複製して利用できる。
